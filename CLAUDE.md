# handdesk

Immersive Mac desktop on Quest 3 by hand tracking. Read `docs/specs/handdesk-v0.1.md` (contract and acceptance checks) and `docs/decisions.md` (why) first.

- `web/` TypeScript + Vite + three.js. `src/gesture` and `src/keyboard` stay pure (no DOM, no three): they are unit-tested on synthetic joints (`tests/fixtures.ts`). Fast tier: `cd web && npm test`. Full: `npm run check && npm test && npm run build && npm run e2e` (devbox: `export PLAYWRIGHT_BROWSERS_PATH=/home/node/work/.devbox/ms-playwright`).
- `agent/` SwiftPM, macOS only. `HandDeskCore` has no capture or CGEvent code: it is tested with a fake `EventPoster` by `swift run core-tests` (no XCTest on a Command-Line-Tools Mac). Build and test over `ssh mac` (rsync `agent/` to a scratch dir, no sudo). Never open a `/ws` session in a test: it triggers the Screen Recording prompt.
- The wire protocol lives in the spec, `web/src/protocol.ts` and `agent/Sources/HandDeskCore/Messages.swift`: change all three together. A test reads the Swift key table to prove every virtual key has a Mac key code.
- The canvas must stay under `#ui` (z-index, pointer-events none), or a desktop click never reaches the Enter buttons.
- Thresholds in `gesture/config.ts` and `keyboard/press.ts` are starting values; tune on the headset, not in tests.
- Window panels spawn near the head (`space/windows.ts`) and are not part of `arrange`; the display row is the only thing recenter moves. Raising a window uses the Accessibility API (`RealSystem.raise`), synchronously, because the click right after must hit it. Probe a live agent with a Node script over `ws://localhost:8787/ws?t=<token>` (header `Origin: http://localhost:8787`), read the token from the file, never print it.
- The v0.3 gestures live in `gesture/extra.ts` (+ `extraConfig.ts`), separate from the classifier. The test fixture hand is a right hand lying palm up; tests mirror and rotate it (`tests/v03.test.ts`).
- Skinned hand meshes are in `web/public/hands` and served from `/hands/`; the agent's static server falls back to `application/octet-stream` for `.glb`, which three.js accepts.
- Installing on the Mac: `scripts/sign-mac.sh` only signs (`--show-bin-path` does not build), so run `swift build -c release` and `npm run build` (node is in `/opt/homebrew/bin`, not on the ssh PATH) first, then `launchctl kickstart -k gui/$(id -u)/online.hrabovskyi.handdesk`. Check the new build with the `raise_result` style log events, not the binary's mtime.
- v0.3.3: the default hand is the glove in `hands/glove.ts` (our joints, no model). Depth sensing is requested only when the saved hand mode is `real`, so after changing that mode re-enter the session. Snips live in `src/snip/`: `Panel.crop` maps every hit to source coordinates, so never add a second coordinate path for them; `SnipView` shares the source `PanelView.texture`. `main.ts` keeps `sourceViews()` (displays and windows: layout) apart from `allViews()` (also snips: grab and handles). Tests: `tests/v032.test.ts`. To eyeball the glove without a headset, render `GloveHands` in a throwaway html under vite and screenshot it with Playwright (`--use-gl=swiftshader`).

- Pointing and clicking come from the WebXR `select`/`squeeze` events and `inputSource.targetRaySpace` (`input/pointer.ts`), queued by the session listeners and consumed in the frame loop; do not turn classifier `click`/`drag-*` events back into Mac clicks (that was "clicking nonsense", D33). What each hand may do is `modes/modes.ts` `policyOf`; a new way to drive the Mac is a new mode there, not a new always-on gesture.
- The new input and feedback logic is pure and tested in `tests/v04.test.ts` (router, trackpad, arrange drag, wrist flip, surface maths, HUD text); the three.js parts are `app/feedbackView.ts`. `space/surface.ts` `surfaceAt` is the one place that turns panel x,y into a world point on a curved panel (cursor, ripple, outline); `main.ts` `surfacePoint` is flat and only for touch dots.
- v0.3.6 UI: the main menu, first-run guide, gesture sheet and Menu button are `ui/` Surfaces (zones: `ui/zones.ts` pure, layout in `ui/deck.ts` and `ui/guide.ts`, drawing `ui/draw.ts`). A button is a zone id; `main.ts` `surfaceAction` maps ids to actions. Router `ui` actions carry x and y. Wrist flip toggles the menu; `launcher` is still the old row list (typing a search). To eyeball: `export PLAYWRIGHT_BROWSERS_PATH=...; cd web && node scripts/shots.mjs <outdir>` (vite dev + `preview.html`, never in the build). The canvas fonts are listed in `draw.ts` (headless Chromium has no system-ui sans). Tests: `tests/v06.test.ts`.

- v0.3.7: the Menu is the orb (`chip` Surface, look "orb") by the left wrist and the radial (`ui/radial.ts`); the deck is only the detail panel behind a radial item. Every Mac panel has a title-bar Surface (`ensureBar`/`barOwner` in `main.ts`; bars live in `uiPanels`, so the select ray hits them). Fades go through `fadeIn`/`fadeOut`: never `scene.remove` an extra directly. Cap and panic in `ui/rescue.ts` (`MAX_EXTRAS`, `HoldOnce`, `ButtonTapHold`). Surfaces take a look (`panel|orb|radial`), not a chip flag. Tests: `tests/v07.test.ts`.
- v0.4.0: there is no orb. The Menu opens from the left palm (`input/palmMenu.ts`, pure, tested), controller B/Y, or the Menu handle on the screen frame (the non-closable bar in `ensureBar`/`updateBars`). The radial `Surface` (look "radial") keeps flat zones but draws nothing: `ui/radial3d.ts` renders its discs; `Surface.setWidth` resizes it (0.4 m palm, 0.7 m front). Panels get a glass slab (`space/glass.ts`, `Glass`) as a child of their mesh; fades skip `userData.noFade` and honour `userData.baseOp`; `space/tilt.ts` `headRef` is set each frame. The look is `ui/style.ts` only: no hex colours in draw code. Window/snip flights are `flyFromScreen`/`updateFlights` in `main.ts`. Eyeball: `node scripts/shots.mjs <dir> room="s=room"` (also `s=radial&hover=r:modes`, `s=deck&tab=windows`). Tests: `tests/v08.test.ts`. `git worktree add` under `.claude/worktrees/`; run edits from the worktree path, not the main checkout.
